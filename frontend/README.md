# Frontend

A React single-page app, built with Vite, that talks to the ALU contracts through ethers.js v6. It has no server of its own: the static files run entirely in the browser, which reads from a public Ethereum node and asks the user's wallet to sign transactions. Setup and usage are in the [main README](../README.md).

## How the code is organised

```
src/
  main.jsx                  mounts the app inside the router and the wallet provider
  App.jsx                   header (navigation, wallet button), network banner, pages, footer
  config.js                 chosen network, deployment addresses, example shareholders
  styles.css                all styling
  contracts/                ABIs and deployment addresses, generated by scripts/export-frontend.js
  wallet/WalletContext.jsx  wallet state shared by every page
  lib/                      plain JavaScript with no React in it, so the tests can import it
    contracts.js            contract objects for reading and for signing
    hash.js                 SHA-256 of a file in the browser, and parsing a pasted hash
    verification.js         verifyLogoIntegrity result turned into what the page shows
    shares.js               token reads, distribution checks and the distributeShares call
    format.js               shortened addresses, numbers with separators, dates
    errors.js               wallet and contract errors turned into plain sentences
  components/               pieces used by several pages
  pages/                    VerifyPage, RegisterPage, DashboardPage
```

The split between `lib/` and the React files is deliberate. Everything that touches the blockchain or computes something lives in `lib/` as ordinary functions that take a contract object as an argument. The pages only hold form state and decide what to show. This is what lets the Hardhat tests run the frontend's real verification, hashing and distribution code against a test chain.

## Contract objects: reading and signing

[src/lib/contracts.js](src/lib/contracts.js) builds contract objects from the ABIs in `src/contracts/`:

* `registryContract()` and `tokenContract()` with no argument use a `JsonRpcProvider` connected to the public Sepolia node from `config.js`. A provider can only make read-only calls (`eth_call`), which cost nothing and need no wallet, so every visitor can use them.
* `registryContract(signer)` and `tokenContract(signer)` use a signer from `walletSigner()`, which wraps `window.ethereum` in a `BrowserProvider`. Calling a non-view function on such an object makes ethers build the transaction and send it to the wallet with `eth_sendTransaction`; the wallet shows it to the user and signs it only if they approve.

`walletSigner()` creates a new `BrowserProvider` on every call. An ethers provider remembers the network it started on and throws "network changed" if the wallet switches network afterwards, so creating it at the moment of signing always gives a provider for the wallet's current network.

The ABI tells ethers each function's name, argument types and return types. Without it ethers could not encode `registerAsset("ALU Official Logo 2026", "PNG", 0x...)` into the 4-byte function selector followed by the encoded arguments, or decode the `(bool, string)` that `verifyLogoIntegrity` returns. The ABI also lists the contract's custom errors, which is how a rejected `distributeShares` from a non-owner comes back decoded as `OwnableUnauthorizedAccount`.

## Wallet connection

[src/wallet/WalletContext.jsx](src/wallet/WalletContext.jsx) keeps the wallet state in one React context, so the header, the banner and every page see the same account:

* On load it calls `eth_accounts`, which returns the account the user already approved without opening a popup, and `eth_chainId`.
* `connect()` calls `eth_requestAccounts`, which opens the wallet's approval window.
* It listens to the wallet's `accountsChanged` and `chainChanged` events. An empty account list means the user disconnected or locked the wallet; a new chain ID updates `isCorrectNetwork`, which shows or hides the network banner and enables or disables the forms.
* `switchNetwork()` sends `wallet_switchEthereumChain`. Error 4902 means the wallet does not know the network (the case for a local Hardhat node), so it then sends `wallet_addEthereumChain` with the network's details.
* `disconnect()` sends `wallet_revokePermissions`, which MetaMask supports, then clears the account.
* `refreshBalance()` reads the account's ALUT balance through the read-only provider. It runs whenever the account changes and after a distribution.

[src/components/WalletButton.jsx](src/components/WalletButton.jsx) shows **Connect Wallet**, or the shortened address, the ALUT balance and **Disconnect**. If `window.ethereum` does not exist, clicking Connect explains how to install a wallet. [src/components/NetworkBanner.jsx](src/components/NetworkBanner.jsx) is the wrong-network banner with its switch button.

## Hashing in the browser

[src/lib/hash.js](src/lib/hash.js):

```js
const bytes = await file.arrayBuffer();
const digest = await crypto.subtle.digest("SHA-256", bytes);
```

`file.arrayBuffer()` reads the selected file's bytes in memory and `crypto.subtle.digest` is the Web Crypto API built into every modern browser. The 32-byte digest is converted to 64 hexadecimal characters with a `0x` prefix, which is the form ethers accepts for a Solidity `bytes32`. Nothing is uploaded anywhere. `parseHash()` accepts a pasted hash with or without `0x`, in either case, and returns `null` unless it is exactly 64 hexadecimal characters.

[src/components/FilePicker.jsx](src/components/FilePicker.jsx) is the file chooser used by both the Verify and Register pages: it shows a preview through a temporary object URL (on a checkerboard, since the ALU logo is white on a transparent background), hashes the file and hands the file and hash to the page.

## Verify page

[src/pages/VerifyPage.jsx](src/pages/VerifyPage.jsx) never uses the wallet. When a file is chosen, or a hash is pasted, it calls `verifyLogo(registryContract(), logoTokenId, hash)` from [src/lib/verification.js](src/lib/verification.js), which:

1. calls `verifyLogoIntegrity(tokenId, hash)` and reads the `bool`;
2. if the logo is authentic, also calls `getAsset(tokenId)` for the name, registration time and registering wallet;
3. returns the title, a plain-language explanation and the details for [src/components/VerificationResult.jsx](src/components/VerificationResult.jsx) to show in green with a check mark, or in red with a warning sign.

The page avoids raw hex: the file's hash is only shown inside a closed "Technical details" section, and the registering wallet is shortened and linked to Etherscan.

## Register page

[src/pages/RegisterPage.jsx](src/pages/RegisterPage.jsx):

1. When a file is chosen, the read-only content hash field is filled with its hash, the file type is suggested from the extension, and `isHashRegistered(hash)` is checked. A duplicate is reported straight away and the button stays disabled, so the user is never asked to pay for a transaction that would revert.
2. On submit it gets a signer and calls `registerAsset(name, fileType, hash)`. The wallet opens for approval.
3. It waits for the transaction to be mined, then reads the token ID from the `AssetRegistered` event in the receipt (`registeredTokenId()` in `contracts.js`) and shows it with an Etherscan link to the transaction.
4. Any error goes through `friendlyError()` from [src/lib/errors.js](src/lib/errors.js): a rejected request, a lack of ETH for gas, or the contract's revert reason ("This file has already been registered" and the others) becomes a sentence.

## Shares dashboard

[src/pages/DashboardPage.jsx](src/pages/DashboardPage.jsx) loads, through the read-only provider:

* `owner()` and `totalSupply()`;
* `balanceOf()` and `ownershipPercentage()` for the owner, the example wallets in `config.js` and anyone the owner sent shares to in this session (`readHolder()` in [src/lib/shares.js](src/lib/shares.js));
* the same two values for the connected wallet, for the "Your balance" and "Your ownership" cards.

The distribution form is inside a `<fieldset>` that is disabled unless the connected account equals `owner()` and the wallet is on the right network. A non-owner sees a message naming the owner. On submit, `checkDistribution()` rejects an invalid address, a non-whole or zero amount, or more shares than the owner holds; then `distributeShares()` sends the transaction and waits for it. Afterwards the dashboard reloads and the header balance refreshes.

The real protection is in the contract: `distributeShares` has OpenZeppelin's `onlyOwner` modifier, so a transaction from any other wallet reverts with `OwnableUnauthorizedAccount` whatever the frontend does. The disabled form only spares a non-owner a failed transaction.

## Configuration

[src/config.js](src/config.js) chooses the network from `VITE_NETWORK` (`sepolia` by default, or `localhost`), takes that network's addresses from `src/contracts/deployments.json`, and lists the example shareholders shown on the dashboard. To show another wallet on the dashboard, add it to `EXAMPLE_HOLDERS` with a label.
